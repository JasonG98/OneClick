# OneClick Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付一个可在真实 Finder 中使用的原生右键工具，具有 Liquid Glass 配置窗口，并准备 Homebrew Cask 分发。

**Architecture:** 一个 SwiftUI 主应用嵌入一个 Finder Sync 扩展。共享 Swift 类型负责配置、选择解析、应用查找及动作执行，扩展使用系统接口完成操作；遇到已验证的沙盒限制才将必要动作交给主应用。

**Tech Stack:** Swift 6.3、macOS 26、Apple Silicon（arm64）、SwiftUI、Liquid Glass、FinderSync、AppKit、Foundation、Observation、Swift Testing、Xcode 26.6。

**Spec:** `docs/superpowers/specs/2026-09-10-oneclick-design.md`

## Global Constraints

- 最低 macOS 26；主应用、Finder 扩展、测试及正式产物仅支持 arm64。
- 应用运行时不引入第三方依赖。
- 一个原生配置窗口；不增加菜单栏常驻图标或独立后台守护进程。
- 在配置窗口中使用系统 Liquid Glass 工具栏、按钮与必要的 `glassEffect`；Finder 菜单外观交由系统管理。
- 普通应用通过 NSWorkspace 打开；Claude Code 使用官方 `claude-cli://open?cwd=`，沿用 Claude 最近使用的终端。
- 第一阶段通过自有 Homebrew tap 的 Cask 分发。
- 当前只验证过开发环境和接口资料；没有应用构建或运行验证结果。
- 在 Apple Silicon 上分别记录不同 Finder 目录的运行验证，不以编译成功代替运行成功。

公共接口：

```swift
struct SelectionContext: Sendable {
    let urls: [URL]
    init(selected: [URL], targeted: URL?, isContainer: Bool)
    var pathText: String { get }
    func workingDirectories() throws -> [URL]
}

enum ClaudeLink {
    static func make(directory: URL) throws -> URL
}

enum TargetKind: String, Codable, Sendable {
    case application, terminal, claude
}

struct OpenTarget: Codable, Identifiable, Sendable {
    let id: String
    var name: String
    var kind: TargetKind
    var bundleIdentifier: String?
    var applicationURL: URL?
    var isEnabled: Bool
}

struct Settings: Codable, Sendable {
    var version: Int
    var targets: [OpenTarget]
    var copiesPaths: Bool
    var directories: [URL]
}

struct SettingsRepository {
    init(fileURL: URL)
    func load() throws -> Settings
    func save(_ settings: Settings) throws
}

@MainActor
struct ApplicationResolver {
    func applicationURL(for target: OpenTarget) -> URL?
}

@MainActor
struct ActionExecutor {
    func open(_ target: OpenTarget, selection: SelectionContext) async throws
    func copyPaths(_ selection: SelectionContext) throws
}
```

- [ ] 先写下列选择测试，建立能编译的最小接口后运行并确认因功能缺失失败：

```swift
@Test func copyPreservesNames() {
    let a = URL(fileURLWithPath: "/tmp/中文 O'Brien & #notes.txt")
    let b = URL(fileURLWithPath: "/tmp/second.txt")
    let selection = SelectionContext(selected: [a, b], targeted: nil, isContainer: false)
    #expect(selection.pathText == "/tmp/中文 O'Brien & #notes.txt\n/tmp/second.txt")
}

@Test func backgroundUsesCurrentFolder() {
    let current = URL(fileURLWithPath: "/tmp/current", isDirectory: true)
    let stale = URL(fileURLWithPath: "/tmp/stale.txt")
    let selection = SelectionContext(selected: [stale], targeted: current, isContainer: true)
    #expect(selection.urls == [current])
}

@Test func claudeLinkRoundTripsDirectory() throws {
    let directory = URL(fileURLWithPath: "/tmp/中文 & #project", isDirectory: true)
    let url = try ClaudeLink.make(directory: directory)
    let parts = try #require(URLComponents(url: url, resolvingAgainstBaseURL: false))
    #expect(parts.scheme == "claude-cli")
    #expect(parts.host == "open")
    #expect(parts.queryItems == [URLQueryItem(name: "cwd", value: directory.path)])
}
```

- [ ] 实现背景与选中项分支、原样路径拼接和 URLComponents 编码；路径保持为数据，不生成 shell 命令。为真实临时文件夹中的多个文件补充工作目录去重测试，为符号链接、失效路径和网络/控制字符输入补充拒绝或保留语义测试。完成红→绿循环。
- [ ] 为 NSWorkspace 打开、Terminal 目录打开、Claude 深链接和 NSPasteboard 写入添加薄适配层。保存菜单生成时的选择快照，动作使用快照，不能异步读取已经失效的 Finder 选择。
- [ ] 实现 `menu(for:)`，仅在存在有效目标时显示两个入口。普通应用过滤不可用目标；菜单构建不能等待外部进程、扫描文件树或请求网络。
- [ ] 写 `script/build_and_run.sh`：使用确定的项目内 DerivedData，先结束本项目运行实例，再 xcodebuild 和 `open` 应用 bundle；支持 `--verify`、`--debug`、`--logs`、`--telemetry`。随后创建环境文件指向该脚本。
- [ ] 运行 `xcodebuild -project OneClick.xcodeproj -scheme OneClickTests -destination 'platform=macOS' -derivedDataPath .build/DerivedData test`；确认测试通过后运行 `./script/build_and_run.sh --verify`。
- [ ] 通过系统界面启用扩展；用项目内测试文件验证真实 Finder 菜单、复制结果、编辑器打开、Terminal cwd 和 Claude cwd。只启动 Claude 会话，不发送提示。
- [ ] 若必要操作被沙盒拒绝，先保存实际错误；将该操作改为 App Group 一次性类型化请求并唤醒主应用，再重复原失败场景。禁止直接扩大成任意命令执行桥。

**Consumes:** Task 1 的类型化目标、真实扩展生命周期。
**Produces:** 主应用关闭后仍生效的目标顺序、启用开关、复制开关和目录集合。

- [ ] 使用原生列表展示应用图标、名称、状态与启用开关，通过移动动作支持排序，工具栏提供添加应用。复制路径开关、Claude 自动终端说明和目录管理保持在同一窗口中。
- [ ] 采用系统 Liquid Glass 主操作样式；下面是启用入口的必要 API 形状：

```swift
Button("启用 Finder 扩展", systemImage: "puzzlepiece.extension") {
```

- [ ] 只在需要自定义玻璃交互表面的区域使用 `glassEffect(.regular.interactive(), in: .rect(cornerRadius: 16))`；相邻自定义玻璃元素置于同一个 `GlassEffectContainer`。系统列表不额外覆盖模糊或不透明底色。
- [ ] 状态始终来自实际扩展状态和 Launch Services；未注册 Claude handler 时显示具体设置说明。失败可通过主应用原生提示呈现；成功操作不弹出提示。
- [ ] 构建运行后检查窗口截图及真实交互：浅色/深色、降低透明度、增强对比度、窗口缩小、键盘 Tab/Space、VoiceOver 标签和应用排序。不得用 UI 结构或颜色断言测试代替视觉与交互检查。
- [ ] 从项目启动入口验证主应用可以正常前台显示，关闭配置窗口不影响扩展；记录 UI 验证并提交。

## Task 4: Homebrew 发布准备与最终验收

**Files:** release.sh、generate_cask.sh、README、docs/releasing.md、docs/verification.md。
**Consumes:** 已验证的 app 与 appex。
**Produces:** 可重复的 Release 构建/归档流程、从真实产物生成 Cask 的脚本，以及诚实的发布就绪状态。

- [ ] 运行 Release 构建，指定 `ARCHS=arm64 ONLY_ACTIVE_ARCH=NO`；通过 `lipo -archs` 检查主程序和扩展的架构输出均仅为 `arm64`，验证 bundle 内嵌结构及元数据。
- [ ] 发布脚本从外部接收 Team ID、签名身份与公证 keychain profile；缺少值时停止公开分发步骤并输出所缺名称。不得把凭据写入仓库或将 ad hoc 产物标成已公证。
- [ ] 签名由 Xcode 管理嵌套代码；导出后运行 `codesign --verify --deep --strict`。公证使用 `xcrun notarytool submit ... --keychain-profile ... --wait`，然后 `xcrun stapler staple` 和 `xcrun stapler validate`，最后 `spctl --assess --type execute`。
- [ ] 用 `ditto -c -k --keepParent` 生成 `.app` 的 ZIP。Cask 生成器接收版本、HTTPS Release URL、主页与归档路径，计算 SHA-256 并输出包含最低系统版本、仅限 arm64 的架构要求及 `app "OneClick.app"` 的 Cask；拒绝不存在的归档或不合规 URL，不使用 `sha256 :no_check`。
- [ ] 在 GitHub 仓库与 tap 账号确定、签名公证成功后，以实际 Release 测试下载、Cask 安装/升级/卸载；此前产物明确标为本地开发构建，Cask 明确标为未发布。
- [ ] 重跑必要的行为测试和 Release 构建。逐项记录本地项目、Downloads、Desktop、Documents、可用外置盘及 iCloud/File Provider 目录；不可测项目标明未验证。
- [ ] 完成代码审查，重点检查跨进程配置更新、文件访问、错误可见性、URL 编码、多选、扩展生命周期与签名设置。修复有证据的问题后仅重跑受影响验证。
- [ ] 交付本地应用、运行入口、验证记录与 Homebrew 发布准备；真实远程发布只在发布输入齐备时完成。
